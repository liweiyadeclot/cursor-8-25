# 如何在 Dify 中查看 400 错误的详细信息

## 🔍 查看错误详情

### 方法 1：在 HTTP 请求节点中查看响应

1. **运行工作流**
2. **点击 HTTP 请求节点**
3. **查看"响应"标签**
4. **复制完整的 JSON 响应**

响应格式：
```json
{
  "success": false,
  "error": "具体错误信息",
  "received": {
    "excel_path": "...",
    "sheet_name": "...",
    "serial": "..."
  },
  "debug": {
    "file_exists": true,
    "file_size": 12345
  }
}
```

---

### 方法 2：在代码节点中输出响应

在处理 HTTP 响应的代码节点中：

```python
import json

# 获取 HTTP 响应
http_response = inputs.get('http_response', {})

# 输出完整响应（用于调试）
output = {
    "debug_response": http_response,
    "response_type": type(http_response).__name__,
    "response_str": str(http_response)[:1000]  # 前1000字符
}
```

---

### 方法 3：查看服务日志

服务启动后会显示请求日志，包含：
- 接收到的请求体
- 处理过程中的错误
- 返回的响应

---

## 📋 常见 400 错误信息

### 错误 1：未能生成提示词

```json
{
  "error": "未能生成序号 1 的 MCP 提示词",
  "suggestion": "请检查 Excel 数据和序号是否正确"
}
```

**可能原因**：
- 序号存在但数据不完整
- 缺少必需字段（如业务大类、项目号等）

**解决**：
1. 检查 Excel 中该序号的数据
2. 确认所有必需字段都有值

---

### 错误 2：文件不存在

```json
{
  "error": "Excel 文件不存在: ..."
}
```

**解决**：
1. 检查文件路径是否正确
2. 确保文件在本地服务可访问的位置

---

### 错误 3：缺少字段

```json
{
  "error": "缺少必需字段: excel_path",
  "received": {...}
}
```

**解决**：
1. 检查 Dify 变量是否正确传递
2. 检查 HTTP 请求体配置

---

## 🔧 快速修复

### 如果错误是"未能生成提示词"

1. **运行诊断工具**：
   ```bash
   python diagnose_400_error.py
   ```

2. **检查 Excel 数据**：
   - 打开 Excel 文件
   - 找到对应序号
   - 检查是否有空值

3. **尝试其他序号**：
   - 测试序号 2、3 等
   - 确认是否所有序号都有问题

---

## 📝 下一步

根据错误信息中的 `error` 字段，采取相应措施：

- **文件不存在** → 检查文件路径
- **序号不存在** → 检查序号
- **未能生成提示词** → 检查 Excel 数据完整性
- **缺少字段** → 检查 Dify 配置

---

## 💡 提示

如果诊断工具显示一切正常，但 Dify 仍然返回 400 错误，请：

1. **查看完整的错误响应**（包含 `received` 和 `debug` 字段）
2. **对比诊断工具的输出**和 Dify 传递的参数
3. **检查是否有路径格式或编码问题**
